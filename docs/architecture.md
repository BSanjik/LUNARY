# Архитектура LUNARY

## Обзор

LUNARY построен на основе микросервисной архитектуры с четким разделением ответственности между компонентами. Система состоит из фронтенда на Flutter, API Gateway для маршрутизации запросов и набора специализированных микросервисов.

## Архитектурные принципы

### 1. Микросервисная архитектура
- **Независимое развертывание** каждого сервиса
- **Изоляция отказов** - проблемы одного сервиса не влияют на другие
- **Технологическое разнообразие** - каждый сервис может использовать оптимальные для него технологии
- **Масштабируемость** - возможность масштабировать сервисы независимо

### 2. API-First подход
- Все взаимодействия происходят через REST API
- Swagger документация для каждого сервиса
- Версионирование API для обратной совместимости

### 3. Безопасность
- JWT токены для аутентификации
- API Gateway как единая точка входа
- Валидация на каждом уровне

## Потоки данных

### 1. Регистрация пользователя
```
Flutter App → API Gateway → Auth Service → PostgreSQL
                ↓
            JWT Token ← ← ← ← ← ← ← ← ← ← ←
```

### 2. Поиск сценариев
```
Flutter App → API Gateway → Auth Service (валидация JWT)
                ↓
            Scenario Service → PostgreSQL
                ↓
            Результаты поиска ← ← ← ← ← ← ←
```

### 3. Загрузка медиа (будущее)
```
Flutter App → API Gateway → Media Service → MinIO Storage
                ↓
            URL файла ← ← ← ← ← ← ← ← ← ← ←
```

## Масштабирование

### Горизонтальное масштабирование
- Каждый микросервис может быть развернут в нескольких экземплярах
- Load Balancer перед API Gateway
- Database clustering для PostgreSQL

### Кеширование
- Redis для кеширования частых запросов (планируется)
- CDN для статических файлов
- Application-level кеширование в сервисах

### Мониторинг
- Health checks для всех сервисов
- Централизованное логирование (ELK stack - планируется)
- Метрики производительности (Prometheus + Grafana - планируется)

## Безопасность

### Аутентификация и авторизация
- JWT токены с коротким временем жизни
- Refresh tokens для продления сессий
- Role-based access control (RBAC)

### Сетевая безопасность
- HTTPS для всех соединений
- API Gateway как единственная точка входа
- Internal network для связи между сервисами

### Защита данных
- Хеширование паролей (bcrypt)
- Валидация входных данных
- SQL injection защита через ORM

## Развертывание

### Docker Containerization
- Каждый сервис упакован в Docker контейнер
- Docker Compose для локальной разработки
- Kubernetes для production (планируется)

### CI/CD Pipeline
- Автоматические тесты для каждого сервиса
- Автоматическое развертывание при merge в main
- Rolling updates без downtime
