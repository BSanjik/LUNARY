# Технологический стек LUNARY

## Обзор

LUNARY использует современный технологический стек, оптимизированный для быстрой разработки MVP, масштабируемости и простоты развертывания. Выбор технологий основан на принципах производительности, надежности и экосистемной зрелости.

## Frontend

### Flutter 3.x
**Назначение:** Кроссплатформенная разработка мобильных приложений

**Обоснование выбора:**
- ✅ **Единая кодовая база** для iOS и Android
- ✅ **Высокая производительность** благодаря компиляции в нативный код
- ✅ **Богатая экосистема** виджетов и пакетов
- ✅ **Google поддержка** и активное сообщество
- ✅ **Rapid prototyping** - быстрое создание MVP
- ✅ **Hot reload** для ускорения разработки

**Альтернативы рассмотрены:**
- React Native: хорошая производительность, но требует больше нативной разработки
- Native development: максимальная производительность, но двойная работа
- Ionic: веб-технологии, но хуже производительность

### Dart
**Назначение:** Язык программирования для Flutter

**Обоснование выбора:**
- ✅ **Оптимизация для UI** - специально создан для фронтенд разработки
- ✅ **Строгая типизация** снижает количество багов
- ✅ **Простой синтаксис** быстрое обучение команды
- ✅ **Отличная интеграция** с Flutter экосистемой

## Backend

### Go 1.21+
**Назначение:** Основной язык для микросервисов

**Обоснование выбора:**
- ✅ **Высокая производительность** - компилируется в машинный код
- ✅ **Простота развертывания** - статические бинарные файлы
- ✅ **Отличная concurrency** - goroutines для высоких нагрузок
- ✅ **Быстрая компиляция** - ускоряет цикл разработки
- ✅ **Минимальное потребление памяти** - экономия ресурсов
- ✅ **Богатая стандартная библиотека** - меньше зависимостей
- ✅ **Микросервисы friendly** - идеален для распределенных систем

**Альтернативы рассмотрены:**
- Node.js: хорошая экосистема, но хуже производительность
- Java: enterprise решение, но сложнее развертывание
- Python: быстрая разработка, но медленнее выполнение
- Rust: максимальная производительность, но сложнее изучение

### Web Frameworks

#### Gin 1.9+
**Назначение:** HTTP веб-фреймворк для API

**Обоснование выбора:**
- ✅ **Высокая производительность** - один из самых быстрых Go фреймворков
- ✅ **Простота использования** - минимальный boilerplate код
- ✅ **Middleware поддержка** - легко добавлять функциональность
- ✅ **JSON биндинг** - автоматическая сериализация/десериализация
- ✅ **Активная разработка** - регулярные обновления

**Альтернативы рассмотрены:**
- Echo: схожая производительность, но меньше сообщество
- Fiber: очень быстрый, но менее зрелый
- Chi: минималистичный, но требует больше кода

## База данных

### PostgreSQL 15+
**Назначение:** Основная реляционная база данных

**Обоснование выбора:**
- ✅ **ACID транзакции** - надежность данных
- ✅ **JSON поддержка** - гибкость схемы данных
- ✅ **Полнотекстовый поиск** - для поиска сценариев
- ✅ **Расширяемость** - custom functions, extensions
- ✅ **Отличная производительность** - оптимизированный query planner
- ✅ **Open Source** - нет лицензионных ограничений
- ✅ **Зрелая экосистема** - множество инструментов и библиотек

**Альтернативы рассмотрены:**
- MySQL: популярная, но хуже поддержка JSON и расширений
- MongoDB: NoSQL гибкость, но сложнее консистентность
- SQLite: простота, но не подходит для продакшена

### GORM
**Назначение:** ORM библиотека для Go

**Обоснование выбора:**
- ✅ **Auto migration** - автоматическое создание схемы БД
- ✅ **Query builder** - безопасные SQL запросы
- ✅ **Associations** - простая работа с связями
- ✅ **Hooks** - lifecycle callbacks
- ✅ **SQL injection защита** - автоматическая экранировка

## Безопасность

### JWT (JSON Web Tokens)
**Назначение:** Аутентификация и авторизация

**Обоснование выбора:**
- ✅ **Stateless** - не требует хранения сессий на сервере
- ✅ **Microservices friendly** - легко передавать между сервисами
- ✅ **Standard** - широко поддерживается
- ✅ **Scalable** - подходит для распределенных систем

### bcrypt
**Назначение:** Хеширование паролей

**Обоснование выбора:**
- ✅ **Adaptive hashing** - настраиваемая сложность
- ✅ **Salt included** - защита от rainbow table атак
- ✅ **Time-tested** - проверенная временем безопасность
- ✅ **Go native support** - встроенная поддержка в Go

## Принципы выбора технологий

### 1. MVP-First
- Приоритет быстрой разработке над идеальной архитектурой
- Простота изучения и использования
- Минимальная настройка и конфигурация

### 2. Производительность
- Высокая пропускная способность
- Низкая латентность
- Эффективное использование ресурсов

### 3. Масштабируемость
- Горизонтальное масштабирование
- Stateless архитектура
- Microservices-ready решения

### 4. Надежность
- Проверенные временем технологии
- Активная поддержка сообщества
- Хорошая документация

### 5. Экономическая эффективность
- Open source решения
- Минимальные лицензионные расходы
- Эффективное использование ресурсов
